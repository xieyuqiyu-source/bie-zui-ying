# 双人抬棺（gameId `coffin`）设计方案

状态：第一版已实现（2026-10-31）。房主固定抬前面、25 秒超时判输、排行榜按个人统计。物理参数以 `miniprogram/pages/coffin/rules.js` 为准，本文的数字是最初设想。

## 1. 玩法

- 横版 2D，canvas 绘制。两个抬棺人一前一后，棺材里躺着一个人，整队自动往右走。
- **合作**：两人一起赢或一起输。不配机器人，大厅里没有「打机器人」按钮。
- 房主是**前面**的人，客人是**后面**的人（固定，不用选角色）。
- 每人 4 个按钮：蹲下 / 半蹲 / 直立 / 跳。前三个是持续状态，按一下切换；跳是一次性动作，跳完落回之前的状态。
- 棺材里的人掉到地上 → 立刻判输。
- 时间限制 25 秒（走到坑边约 20 秒，留 5 秒倒人）。超时没倒进坑 → 判输。
- 胜利：棺材里的人落进终点的坑。

## 2. 关卡

固定一条赛道（两边一样，不用同步地形）。整队匀速前进，约 20 秒走到坑边后停下。

| 段落 | 时间 | 内容 | 正确姿势 |
| --- | --- | --- | --- |
| 平地 | 0–3 秒 | 热身 | 两人同高 |
| 上坡 | 3–7 秒 | 约 12° | 前蹲、后站 |
| 平地 | 7–9 秒 | | 同高 |
| 下坡 | 9–13 秒 | 约 12° | 前站、后蹲 |
| 小坎 | 13–16 秒 | 两个凸起，前后脚先后经过 | 经过时临时蹲一下 |
| 平地 | 16–20 秒 | | 同高 |
| 坑 | 20 秒起 | 队伍停在坑边，坑在前方 | 前蹲、后站，再猛地起身/跳 |

先做一条，玩起来再调。后面可以加多条赛道，用房间 id 选。

## 3. 物理（手写，不引入库）

固定步长 60Hz，单位用米。

- **抬棺人**：脚踩在地形上，肩高由姿势决定：蹲 0.6、半蹲 0.85、站 1.1，跳的时候额外向上冲约 0.35 再落回。肩高不会瞬间变化，按最大速度（约 3 m/s）逼近目标高度。这个速度就是"快起快蹲"的手感来源：起身越猛，棺材那头的竖直速度和加速度越大。
- **棺材**：一块长 2 米的刚性板，两头架在两人肩上，没有自己的动力学。两端有矮挡板（头和脚各一块）。
- **棺材里的人**：一个质点（画成躺着的人），放在棺材坐标系里，有两个状态：
  - **贴板**：沿板滑动，受重力分量和摩擦力。板太陡就开始滑，撞到挡板会反弹一点（反弹系数 0.3）。
  - **腾空**：板的法向加速度向下超过重力时（即板被猛地往下撤），或者人被板猛地往上顶、板随后减速时，人离开板变成抛体。落回板面范围内就重新贴板。
- **失败判定**：腾空的人落到地面，或者滑过挡板（挡板高度以上越出去）掉下来。
- **胜利判定**：人落进坑的范围内。

所有参数（肩高、摩擦、挡板高、最大升降速度）放在一个 `rules.js` 里，方便调手感。

## 4. 双人同步

**房主算物理，客人只发操作。**

- 客人按按钮 → 发 `coffin:input { pose }`（`crouch | half | stand | jump`）。
- 房主每帧跑物理，每 50ms 发一次 `coffin:state`：`t`（开局后毫秒数）、两人肩高、人的位置/速度/状态。客人按 100ms 缓冲做插值显示。
- 客人自己那个人的肩高本地立刻变化（只是显示），棺材和人的位置以房主状态为准。
- 结束时房主发 `coffin:end { result, atMs, reason }`，两边都跳结果页。
- 延迟：客人的操作到房主那里大约多出 50–150ms。这个玩法靠配合，影响不大。实测后再决定要不要补偿。
- 房主掉线：客人等 3 秒收不到状态，显示「前面那位跑了」，按超时判输。

服务端在 `roomSocketService` 里集中处理这三个类型：只允许房主发 `coffin:state` / `coffin:end`，只允许客人发 `coffin:input`，数值全部 clamp，字段白名单，其余丢弃。

## 5. 后端

### `src/games/coffin.ts`

- `durationSeconds: 25`，`betterScore: "lower"`（分数 = 通关用时，毫秒；越短越好）。
- `normalizeSubmission`：客户端提交 `score`（用时毫秒）和 `trace: [result]`（1 成功 / 0 失败）。用时必须在 [`MIN_CLEAR_MS`（约 20 秒，物理上不可能更快）, 25000] 内，否则当失败。
- `judge`：**只认房主的提交**（他是物理权威）。房主没交 → 失败。
- `botSubmission`：不会被调用（不能建机器人房），直接抛 `BOT_NOT_SUPPORTED`；`/api/rooms/bot` 对 `coffin` 返回同样的错误码。

### 合作结算（需要改通用层）

现在的 `Judgement.winner` 只能是一方赢、一方输或平局。合作游戏需要「两人都赢 / 两人都输」：

- `GameDefinition` 加 `cooperative?: true`。
- `Judgement` 加 `team?: "win" | "lose"`。合作游戏的 `winner` 固定为 `null`。
- `roomService` 结算时：`cooperative` 游戏按 `team` 给两人都记 win 或都记 loss，`matches.result_type` 新增取值 `coop_win` / `coop_lose`（列是 VARCHAR 还是 ENUM 动手前确认，ENUM 要在 `initDatabase()` 里幂等 ALTER）。
- 排行榜：`wins`（通关次数）和 `bestScore`（最快通关，ASC）。按组合排名要新表，先不做，以后再说。

### 战报文案

成功：「棺材板都没晃，这俩是职业的。」失败：按 `reason` 区分，比如「前面那位起太猛，人直接飞了」「后面那位蹲太快，人滑出去了」。失败原因由房主根据最后一次大幅动作是谁做的来判断，写进 `detail`。

## 6. 前端页面

```text
miniprogram/pages/coffin/
  lobby/    大厅：建房、输房间码、规则说明、排行榜入口
  room/     等待房间：显示谁在前谁在后、准备、分享
  play/     游戏页：canvas + 底部 4 个按钮
  result/   结果页：成功/失败、用时、甩锅文案、再来一局
  rules.js  赛道和物理参数
  physics.js 物理步进（纯函数，房主用；以后也能拿来离线调参）
```

- `games.js` 加一项：`id: "coffin"`，`name: "双人抬棺"`，`glyph: "棺"`，`accent` 暂定 `#5b3a29`（棺木棕），`tags: ["双人合作", "物理", "20 秒"]`。
- 房间页和结果页先看追赶巴士（另一个会话正在做）是怎么组织的，能复用就复用。
- 按钮用 `bindtouchstart` 而不是 `bindtap`，少一点延迟。

## 7. 开工顺序

1. `physics.js` + 一个单机调试页（一台手机同时控制两个人），先把手感调出来。这一步不碰后端。
2. 后端：合作结算通用化 + `coffin.ts` + WS 消息。
3. 双人同步、房间页、结果页。
4. 两台手机实测，调延迟和参数。
